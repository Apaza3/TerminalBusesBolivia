## Resumen del Sprint 2

Este sprint implementa el sistema dinámico de gestión de flota (buses con layout configurable) y el módulo de registro de tripulación. El objetivo es pasar del layout estático (`CONFIG_BUS_ESTANDAR`) a un sistema donde cada bus tiene su propia configuración en la base de datos.

## Módulo 1: Migración SQL v2.1

### Archivo: `backend/v2_1_migracion.sql`

#### Cambios en tabla `buses`
| Columna nueva | Tipo | Default | Descripción |
|---------------|------|---------|-------------|
| `pisos` | INT CHECK (1,2) | 1 | Número de pisos del vehículo |
| `columnas` | INT CHECK (3,4) | 4 | Columnas de asientos (3=2+1, 4=2+2) |
| `filas_piso_1` | INT | 10 | Filas de asientos en piso 1 |
| `filas_piso_2` | INT | 0 | Filas de asientos en piso 2 (0 si 1 piso) |
| `tiene_bano` | BOOLEAN | false | Presencia de baño en piso 1, parte trasera |
| `amenidades` | TEXT[] | '{}' | Tags: 'WiFi', 'USB', 'AC', 'Bus Cama', 'TV', etc. |

#### Nueva tabla `tripulacion`
```sql
CREATE TABLE tripulacion (
    id          UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    sucursal_id UUID REFERENCES sucursales(id),
    ci          TEXT UNIQUE NOT NULL,
    nombre      TEXT NOT NULL,
    telefono    TEXT,
    rol         TEXT CHECK (rol IN ('conductor', 'copiloto', 'ayudante')),
    licencia_url TEXT,
    foto_url    TEXT,
    activo      BOOLEAN DEFAULT true,
    created_at  TIMESTAMPTZ DEFAULT NOW()
);
```

#### Cambios en tabla `viajes`
- Agregadas columnas FK: `conductor_id`, `copiloto_id`, `ayudante_id` → referencian `tripulacion(id)`.

#### Cambios en tabla `asientos_viaje`
| Columna nueva | Tipo | Descripción |
|---------------|------|-------------|
| `piso` | INT | Piso al que pertenece el asiento |
| `fila` | INT | Número de fila |
| `columna` | INT | Número de columna |
| `numero_asiento` | TEXT | Etiqueta formateada, ej: "3B", "P2-5C" |
| `tipo_asiento` | TEXT CHECK ('normal','semicama','cama') | Tipo de asiento |

#### RLS (Row Level Security)
- `tripulacion`: SELECT público; INSERT y UPDATE habilitados para el prototipo.
- Nota: En producción, restringir INSERT/UPDATE al rol `service_role` o autenticación de admin.

#### Pasos de aplicación
1. Ejecutar `v2_1_migracion.sql` en el SQL Editor de Supabase.
2. Crear el bucket `tripulacion-fotos` en Supabase → Storage (público, acepta JPG/PNG/WebP).

## Módulo 2: Admin — Registro de Tripulación

### Archivo: `frontend/src/paginas/admin/RegistroTripulacion.js`
**Ruta:** `/admin/tripulacion/nuevo`

#### Funcionalidades
- **Formulario:** CI (cédula), nombre completo, teléfono, rol (conductor/copiloto/ayudante).
- **Verificación de CI único:** Consulta `tripulacion.ci` al perder foco del campo. Muestra feedback visual (verde = disponible, rojo = duplicado).
- **Upload de fotografías:** Foto de perfil y foto de licencia subidas al bucket `tripulacion-fotos` en Supabase Storage, con previsualización inmediata.
- **Validación:** CI obligatorio, nombre obligatorio, rol obligatorio. El botón "Guardar" se desactiva si CI es duplicado.
- **Feedback:** Mensajes de éxito/error inline, sin recargar la página.

## Módulo 3: Admin — Registro de Buses

### Archivo: `frontend/src/paginas/admin/RegistroBus.js`
**Ruta:** `/admin/bus/nuevo`

#### Funcionalidades
- **Identificación:** Placa (con verificación de unicidad en DB al perder foco), asignación a sucursal.
- **Configuración de Layout:**
  - Número de pisos: toggle 1 / 2.
  - Columnas: toggle 4 (2+2) / 3 (2+1).
  - Filas piso 1 (siempre) y filas piso 2 (visible solo si pisos=2).
  - Baño: toggle Sí / No.
- **Vista previa en tiempo real:** Usa las mismas clases CSS del `MapaAsientos` (`bus-cuerpo`, `asiento-btn`, etc.) para mostrar una silueta cenital a escala reducida. Se actualiza al cambiar cualquier parámetro.
- **Amenidades:** Multi-select de tags (WiFi, USB, AC, Bus Cama, TV, Baño, Calefacción).
- **Cálculo automático de capacidad:** `capacidad = filasPiso1 × columnas + filasPiso2 × columnas`.
- **Guardado:** Inserta en tabla `buses` con todos los campos del layout.

## Módulo 4: Actualización del Mapa de Asientos

### Archivo: `frontend/src/paginas/MapaAsientos.js`

#### Cambios principales

**1. Lectura dinámica del layout desde Supabase:**
```js
// Nueva query que lee columnas v2.1 del bus
.select(`
    id, origen, destino, salida, precio, duracion_estimada,
    buses (
        id, placa, capacidad,
        pisos, columnas, filas_piso_1, filas_piso_2,
        tiene_bano, amenidades
    )
`)
```
El código mapea automáticamente los campos DB a los campos del objeto `configBus`.

**2. Selector de piso para buses de 2 pisos:**
- Nuevo state `pisoActivo` (1 o 2).
- Al cargar un bus de 2 pisos, aparece un selector visual con 2 botones que muestran cuántos asientos disponibles hay en cada piso.
- El bus muestra solo los asientos del piso activo. El baño aparece solo en piso 1.

**3. Generación de asientos de respaldo:**
- Si `asientos_viaje` está vacío para el viaje, se generan asientos demo basados en el config real del bus.
- Los asientos generados incluyen `tipo_asiento` (75% normal, 25% semicama).

**4. Tipos de asiento:**
- `normal`: sin cambios visuales adicionales.
- `semicama`: borde ámbar sutil (`rgba(251,191,36,.4)`) y overlay de icono 🛏️ en la esquina superior.
